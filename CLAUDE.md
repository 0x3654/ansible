# ansible — правила репозитория

## Структура и загрузка переменных

- Инвентарь — отдельный репо-сабмодуль `inventory/` (пуш: `git push origin HEAD:main`,
  перед пушем main сверять пины сабмодулей).
- `host_vars/<host>.yml` НЕ грузятся автоматически (ansible ищет их рядом с inventory-файлом,
  а запуск идёт с `-i inventory/inventory.yml`) — их поднимает **явная преамбула в каждом
  deploy-плейбуке**:
  ```yaml
  - name: Load host_vars if exists
    ansible.builtin.include_vars: "{{ playbook_dir }}/../host_vars/{{ inventory_hostname }}.yml"
  ```
  Новый deploy-плейбук обязан её иметь. Проверять наличие при ревью.
- Параметры, специфичные для роли на хосте (пути, режимы, контракты) — в `host_vars`,
  не inline в inventory (исключения — связи/группы). Разовые — через `-e` (Make/Semaphore).

## Vault-политика

- `host_vars/<host>.yml` — **всегда целиком в ansible-vault** (без исключений, включая хосты
  «без секретов»: единообразие дешевле рассуждений «а этот секрет секретный ли»).
- Прочие секреты (role secrets) — vault-файлы ролей (`roles/*/vars/secrets.yml`), не plaintext.
- Секрет в plaintext, попавший в git: файл немедленно завалтить + rotation секрета отдельной
  задачей по явной команде владельца (история git остаётся).

## Бэкапы (роль `backup`)

- Хост бэкапит **сам и локально** (launchd/cron 00:30), без сети; ansible — только деплой
  раннера и контрактов. Вынос копий наружу (TM, pull с micro) — отдельные слои.
- Контракт (что/как/retention) декларирует **роль сервиса** (`backup_contract` в defaults +
  set_fact-регистрация), хост-экстра (catch-all) — в `host_vars`. Роль `backup` — последней
  в плейбуке.
- retention — целыми комплектами на item; живые БД — только `kind: pg` (pg_dump), тарить нельзя.

## Прочее

- Коммиты — подписанные (SSH-ключ), сообщения на английском, staging точными путями.
- Пуш/деплой — только по явной команде. Репо Semaphore запинено на main.
- Всё исполняется в контейнерах; ansible-прогоны — из Semaphore или контейнера
  semaphoreui/semaphore с примонтированными ключами.
